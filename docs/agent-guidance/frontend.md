# Frontend Engineering Guidance

- Keep React components focused on presentation and interaction; place reusable state transitions, parsing, and effects in established hooks or utilities.
- Use `useApexData()` for boot configuration and reminders. Use focused hooks for their respective concerns instead of adding to `useApexData()`: `useTelemetryCollectionState()` for the app-session collection-start latch, `usePreflight()` for preflight warning/blocker dialog flow, `useTelemetrySnapshot()` for telemetry snapshots and refresh, `useBriefingSessions()` for session admission, detail polling, and canonical artifact state, `useBriefingSpeech()` for speech status and playback lifecycle, `useWorkspaceView()` for resolving the selected Overview or Briefing presentation and selected briefing profile, `useBriefingPresentation()` for marking a briefing presented once visible, `useCompactLayout()` for the shared compact breakpoint, `useCortex()` for Agent status and catalog, verification, polling, and local-model lifecycle, `useCortexRuns()` for recent runs, active-run polling, and cancellation, `ApexAssistantRuntime` for conversation/thread history, submission, and streaming, `useActions()` for Cortex action list, audit detail, and versioned controls, `useActivityReports()` for external report list/detail and review linkage, `useContextInspector()` for personal-context records, retrieval preparation, reconciliation, and review, `useContextVault()` for vault settings, preview, and publication controls, `useToolCatalog()` for selection and profile state, and `useToolPreflight()` for next-request token estimates.
- Keep `useMarketData()` focused on cache-backed Market display data. It reloads when telemetry publishes a Market collection revision and must not add a competing provider refresh or polling loop. Do not force unrelated state into `useApexData()` or into a hook that owns a different concern.
- Avoid duplicate fetch loops or competing sources of truth for the same backend resource.
- Model loading, empty, error, disabled, demo, and stale states explicitly. Use local progress indicators when a local action is independent; use shared status when the underlying operation is global.
- Preserve keyboard access, semantic structure, meaningful labels, visible focus, adequate contrast, and reduced-motion behavior.
- Build responsive layouts from content constraints and breakpoints. Fixed values are acceptable for bounded primitives such as borders, icons, focus rings, and minimum touch targets; avoid arbitrary fixed dimensions that prevent adaptation.
- Reuse established API constants, visual tokens, and shared components before introducing parallel abstractions.
- Follow `docs/design-system.md` for visual changes while allowing explicit product requirements to override defaults.
- Run `npm test`, `npm run lint`, and `npm run build` from `frontend/` after frontend changes.
